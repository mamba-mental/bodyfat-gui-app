## ADDED Requirements

### Requirement: Dashboard widgets render current metrics
The dashboard SHALL display up-to-date progression statistics across all widget cards and charts after the initial render when valid calculation data exists.

#### Scenario: Baseline dataset available
- **GIVEN** the database contains at least one historical entry and a completed progression calculation
- **AND** the dashboard route `/` is requested from a freshly started stack
- **WHEN** the page finishes loading
- **THEN** weight, body fat, calorie, and timeline widgets display non-zero values that align with the latest calculation snapshot
- **AND** lazy-loaded chart components render without throwing client-side errors.

### Requirement: Persisted profile auto hydration
The application SHALL hydrate the previously saved user profile automatically on startup without forcing the setup flow when profile data exists.

#### Scenario: Returning user session
- **GIVEN** profile details were saved via the setup flow
- **AND** the same environment is reloaded after restarting the local development servers for the frontend and backend
- **WHEN** the dashboard initializes client and server state
- **THEN** the user’s profile header, goals, and preferences appear without visiting `/setup`
- **AND** the theme and other persisted settings match the stored values.

### Requirement: Dashboard becomes interactive within target latency
The dashboard SHALL reach an interactive state within an acceptable performance budget when served from the documented local development environment.

#### Scenario: Local dev cold start
- **GIVEN** the local development servers for the frontend (Next.js) and backend services (Python API and Redis or equivalent) are started using the approved scripts
- **AND** no prior build artifacts are cached in the browser
- **WHEN** a user opens the configured local dashboard URL (for example `http://localhost:3000/`)
- **THEN** the page becomes interactive (hydrated and responsive to input) within 10 seconds
- **AND** no loading spinner or placeholder remains indefinitely on the widgets.

### Requirement: Frontend assets load without chunk errors
The deployment SHALL serve coherent Next.js build artifacts so that dynamic imports and chunks resolve successfully.

#### Scenario: Browser fetches latest build assets
- **GIVEN** the Docker stack uses a freshly built frontend image or volume mount generated by `npm run build`
- **WHEN** the browser requests `_next/static/chunks/*`
- **THEN** all chunk responses complete without `ChunkLoadError`
- **AND** no 404 or network failure is logged for these assets in the browser console or Next.js server output.
